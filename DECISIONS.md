# BOMBA — DECISIONS.md

Append-only. One line per assumption: date, the decision, the reason. Newest at the bottom.

- 2026-09-18 — Godot pinned to 4.7-stable (official build 5b4e0cb0f); it is the latest stable and the version installed on the authoring machine. `config/features` says "4.7".
- 2026-09-18 — netfox v1.35.3 vendored into `addons/` (netfox, netfox.internals, netfox.noray, netfox.extras); `vest` was not vendored because the project has its own tiny headless test runner and does not want a test-framework dependency.
- 2026-09-18 — Authoring happens on macOS even though the target is Windows; nothing in the repo may be platform-specific except the tools scripts, which are plain `sh` and Godot.
- 2026-09-18 — The Godot project root is the repository root so the design documents live next to `project.godot`; `reference/` carries a `.gdignore` so the screenshots never enter the import pipeline.
- 2026-09-18 — Simulation tick rate is 60 Hz (`netfox/time/tickrate=60`) matching the physics tick so `physics_factor` is 1; netfox has no separate snapshot rate, so state is transmitted every tick with diff encoding (see `NETPLAN.md` §9 for the cost).
- 2026-09-18 — Rollback history limit 90 ticks, input redundancy 4, input delay 0, display offset 0: covers the `awful` profile with margin and keeps local response immediate.
- 2026-09-18 — Remote player prediction is off and input broadcast is off: fewer bytes, smaller cheat surface, and a shooter has no use for predicted enemies.
- 2026-09-18 — Conditioner profile numbers are round-trip milliseconds (`good` = 40 ms RTT), applied as half per direction; loss percentage is per direction. "Feels good at 120 ms" in `DESIGN.md` is read as 120 ms ping, i.e. the `bad` profile.
- 2026-09-18 — The network conditioner is our own seeded in-process UDP proxy, not netfox's `NetworkSimulator`, because the latter is editor-only, unseeded and has no jitter.
- 2026-09-18 — Lag compensation is analytic (ray vs recorded head sphere and body capsule) rather than moving physics bodies back in time; it is deterministic, cheap to run during resimulation, and testable without a scene.
- 2026-09-18 — `view_tick` (the remote render tick) is sent by the client as an input property and clamped server-side to 250 ms; that is the only client-supplied timing the hit resolve trusts.
- 2026-09-18 — Look angles are sent as absolute yaw/pitch, not deltas, so a lost input packet cannot permanently drift the aim.
- 2026-09-18 — Deaths and respawns are resolved only by the authority; clients predict damage (for hitmarkers) but never predict a death, so the victim eats the latency.
- 2026-09-18 — Movement numbers: 5.8 m/s walk, gravity 12.5, jump velocity 6.1 (1.49 m, 0.98 s air) derived by scaling Halo 3's ~3.2 body-heights/s to a 1.8 m character; all in `tuning/movement.json` to be tuned by hand.
- 2026-09-18 — Sniper `scope_in_ticks` = 16 (267 ms); the viewmodel tween reads this value so the animation can never disagree with the accuracy rule.
- 2026-09-18 — AR is 600 rpm (6 ticks), 22 near / 12 far damage with linear falloff 12–38 m, 12-shot deterministic recoil pattern; the sniper stays the better pick past ~30 m by design.
- 2026-09-18 — Player identity colours are defined as HSV (value 0.82, saturation 0.72, hues 275/325/15/55/105/195) in `tuning/palette.json`; value stays under the 0.85 ceiling and hue gaps are ≥ 40°.
- 2026-09-18 — The arena gray-box is built from `StaticBody3D` + `BoxMesh` primitives generated in script from a layout table, so the map can be re-shaped without an editor session and never contains ripped assets.
- 2026-09-18 — Type: no display font is shipped yet; the built-in font with a heavy outline stands in. Candidate OFL faces to choose from later are listed in `STATUS.md`. Nothing is downloaded without a licence check.
- 2026-09-18 — Minigames are discovered by scanning `res://minigames/*/manifest.json`; the registry never imports a minigame by name, which is what keeps minigame #12 a zero-change addition.
- 2026-09-18 — `netfox/time/sync_to_physics=true`: the tick loop runs inside the physics step so `physics_factor` is exactly 1.0 and `move_and_slide()` sees the same delta every tick; with the loop in `_process` the factor is `ticktime / frame_delta` and floating-point round-off makes 60 fps and 240 fps trajectories differ in the last bits.
- 2026-09-18 — Players do not collide with each other (layer 2, mask 1 = world only). Player-vs-player pushing would need mutation handling on every contact; a shooter has no need for it, and it removes a whole class of misprediction.
- 2026-09-18 — netfox property paths cannot address a child's nested field (`Head:rotation:x` is rejected by `PropertyEntry.is_valid`), so pitch is a plain `head_pitch` float on the body and the Head node is set from it each tick.
- 2026-09-18 — The determinism harness feeds a seeded per-tick input log through `NetworkTime.before_tick` (`ScriptedInputDriver`), not through bots: bots gather once per tick *loop* by design, so their decisions depend on how many ticks a frame ran, which is exactly the frame-rate dependence the test must not contain.
- 2026-09-18 — Bots and `--autoplay` humans decide once per tick loop (`before_tick_loop`), like a human's input sampling. Good enough for soaks; not a determinism source.
- 2026-09-18 — Rollback node order inside a tick is scene-tree order (players sorted by peer id). A hit registers on the victim's next tick if the victim already ran this tick; that one-tick difference is accepted and identical on every peer.
- 2026-09-18 — Physics engine is Jolt (`physics/3d/physics_engine="Jolt Physics"`), reversing the earlier GodotPhysics3D default: with GodotPhysics3D two identical scripted runs differed by 0.09 mm in resting height where the capsule touched two surfaces (contact-order dependent recovery); with Jolt 60 fps, 60 fps again and 240 fps agree on all 2400 rows, and the tick loop costs a third as much.
- 2026-09-18 — netfox diff-state tuning: `full_state_interval` 12, `diff_ack_interval` 6, `history_limit` 128. At 120 ms RTT with 3 % loss the defaults (24 / 0 / 90) dropped diff states eight times in 30 s because the reference tick had aged out; with these values zero drops and 30 % less bandwidth.
- 2026-09-18 — Remote players' hitbox history is sampled in `NetworkTime.after_tick_loop` from the Player's own handler, which runs after NetworkRollback applied the display state and before TickInterpolator (deferred connection) re-applies the previous state. Sampling anywhere else reads a stale transform; this was measured as a 25 % hit-confirmation rate before the fix.
- 2026-09-18 — HitboxHistory does not interpolate across a jump larger than 2 m (a respawn): a shooter can never hit a ghost half way along a teleport.
- 2026-09-18 — netfox is patched locally (`addons/netfox/PATCHES.md` #1): the rollback recorder no longer records copies of an old state under new tick numbers for nodes nothing simulated. Without it a client's view of remote players (pure state playback, input broadcast off) lagged by whole tick loops: measured 0.9–1.2 m mean error against host truth and a 25–55 % hit-confirmation rate. The patch is documented for re-application on upgrade and is a candidate for upstream.
- 2026-09-18 — After a respawn the fresh body ignores weapon input for `respawn_fire_lockout_ticks` (12 = 200 ms): inputs queued before the client learned of its death were firing from the spawn point and cancelling spawn protection.
- 2026-09-18 — Art numbers from the first screenshot: grain 0.012 (was 0.035, read as static), cel shadow level 0.84 with a lighter cool tint, and most crates in the counter colour so purple stays a small-area accent.
- 2026-09-18 — Clients never call `NetworkRollback.mutate()` on a remote victim. Measured: with the mutation the shooter's view of a victim froze for as long as the shooter kept hitting it (the recorder stored a copy of the stale state under the current tick), producing bursts of predicted hits the server rejected. The hitmarker only needs the local `take_damage` result.
- 2026-09-18 — netfox patch #2 (`PATCHES.md`): the display state is `max(display_tick, latest_state_tick)`. A client whose synced clock trails the host by a few ticks receives states "from the future" and unpatched netfox showed the oldest one; remote players froze on the client for hundreds of ticks while shots still resolved against the frozen ghost.
- 2026-09-18 — `RewindableAction.mutate(player)` is registered only on peers that simulate that player (server, input owner). Measured: with it registered everywhere, a remote player froze on a client's screen whenever they fired (the action's broadcast mutated the playback node and netfox recorded a stale copy over newer states); the bot's client-side position error averaged 3 m.
- 2026-09-18 — Body capsule top lowered to 1.18 m (radius 0.34, so the shape ends at 1.52 m) so the 0.16 m head sphere at 1.62 m is visible and distinct; the hitboxes use the same numbers, and the head sphere is tested first.
- 2026-09-18 — netfox patch #3 (`PATCHES.md`): empty diff states are stored as a copy of their reference and diffs with a missing reference are dropped instead of merged into nothing; partial snapshots were shadowing good history (38–87 warnings per run).
- 2026-09-18 — `RewindableAction.mutate(player)` is registered on the server only. Root cause of the intermittent 130-tick post-death desync on clients: the client's action re-queued a disputed shot tick every loop and mutated the player from it, so netfox re-recorded the client's stale prediction over every authoritative state until the tick left the 128-tick history window. Diagnosed from per-loop `latest_state`/`rollback_depth` rows in `reports/soak_g4_client1_local.csv`.
- 2026-09-18 — A finished minigame is removed from the tree before the next one is added. A queued-free node keeps its name until the end of the frame and Godot's auto-rename for duplicates differs per peer, which would break every RPC path on the second round. Verified with two consecutive 8 s rounds (host + client, identical rankings both times).
- 2026-09-18 — The viewmodel uses a cel shader variant that squashes clip-space depth toward the near plane (`cel_viewmodel.gdshader`, reversed-Z aware) instead of a second camera/viewport: the gun never clips into walls, its parts still depth-test against each other, and the ink post-pass still outlines it. Seen in a screenshot where only the sniper's stock survived a wall.
- 2026-09-18 — Ten reference images were measured (`STYLE.md` appendix): the 0.85 value ceiling holds for surfaces but BRC skies reach V 0.97 in cloud highlights, so the post pass clamps only pixels nearer than the sky distance. Sky/cloud tones in `tuning/palette.json` come from k-means clusters of the reference skies.
- 2026-09-18 — Viewmodel framing follows the three Roboquest shots: gun spanning ~40 % of frame width in the lower-right quarter, pointing to the upper-left at ~20°, an arm from the bottom-right corner, one emissive detail. Roboquest's damage numerals and decals are not taken (STYLE §6: framing only).
- 2026-09-18 — Hit and muzzle feedback are drawn star shapes (ink rim, colour body, white core) built as billboard triangle fans, matching the BRC boost burst; the earlier sphere impact marks are gone.
- 2026-09-18 — Cloud lit/shadow split samples the noise one step *down along elevation* (a world axis): lit where the cloud continues below, shadow on the underside. The first version sampled "above" in the projected plane, which is view-dependent and shaded almost every cloud dark.
- 2026-09-18 — Per-weapon hip framing: the sniper keeps 11° of yaw so its barrel crosses the frame and the silhouette stays long and thin (STYLE §6); the AR sits at 19° like the short Roboquest guns. A single shared angle made the sniper read as a box.
- 2026-09-18 — State replication carries `:position` + `:yaw` (16 + 8 bytes) instead of `:transform` (52 bytes); the node's rotation is derived each tick, and `TickInterpolator` interpolates `:position` only.
- 2026-09-18 — netfox patch #4: `netfox/rollback/state_send_interval = 2` (state at 30 Hz, the snapshot rate DESIGN.md §3 specified). Reason: noray relays cap each relay at 128 kB/s in 100 ms slices and the public instance dies when exceeded; the first two relayed matches collapsed within two seconds of the host's state stream starting.
